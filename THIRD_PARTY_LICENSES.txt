## Runtime Architecture & Zero-Dependency Guarantee

Gardener OS is an operating system substrate built specifically for LLMs. Everything lives in a searchable SQLite database. Four functions are all you need: find, get, put, and run. It is engineered from the ground up to guarantee 100% unprivileged, local-first, zero-egress execution.

The core engine (gardener.py), federated ingestion adapters (sources.py), reference seeding (seed.py, apply_reference_sources.py), local web GUI companion (search_gui.py), sleep union maintenance (sleep_union.py), and CLI internationalization (i18n.py) execute exclusively using the Python Standard Library.

| Component / Runtime | Version Constraint | License | SPDX-License-Identifier | Type | Purpose |
|---|---|---|---|---|---|
| Python Standard Library | >=3.10 | Python-2.0 (PSF) | PSF-2.0 | Standard Library | Core language runtime, sqlite3 FTS5 database substrate, http.server for local zero-egress GUI (127.0.0.1), json, pathlib, hashlib, and argparse. |

Gardener OS ships with 0 external runtime dependencies, eliminating supply-chain attack vectors, unpinned binary surprises, and external telemetry brokers.

## Zero-Copyleft Guarantee & Unprivileged Execution

- Zero-Copyleft Guarantee: All application code, SQLite schema blueprints, FTS5 BM25 tokenizers, federated ingestion adapters, and the local search GUI are governed strictly by permissive, business-friendly open-source licenses (MIT, PSF-2.0, Apache-2.0). The repository contains zero GPL, AGPL, LGPL, SSPL, or viral copyleft components. Developers and organizations can safely embed or bundle Gardener OS into autonomous agent stacks without licensing contamination.
- Unprivileged User-Mode Operation (RunAsInvoker): All Gardener OS commands (gardener find, get, put, run, gui, observe, sync) execute strictly within unprivileged user space. No administrative rights, root elevation, sudo, or UAC prompts are ever required or requested. State is cleanly partitioned into unprivileged user data (~/.gardener/user.db or $GARDENER_DATA/user.db) and system blueprints (~/.gardener/gardener.db). Ephemeral tool executions in workspace/ operate in unprivileged sandboxes with timeout protection and automated cleanup.

## Governance & Runtime Invariants

Gardener OS adheres to ten foundational governance and runtime invariants:
- INV-LOCAL-01: Local-First & Zero Egress (100% offline-first execution; zero telemetry, tracking scripts, or outbound network calls)
- INV-RUNAS-02: Unprivileged User Mode (RunAsInvoker) (Strictly unprivileged execution; no UAC or root prompts required)
- INV-FTS-03: Deterministic FTS5 BM25 Memory (Deterministic SQLite FTS5 BM25 ranking, snippet extraction, and prefix filtering without vector-drift or remote embedding APIs)
- INV-SEC-04: Pre-Index Secret Redaction (13 credential families redacted in sources.py before indexing)
- INV-CLOUD-05: Cloud Leak Alerting (Findings in cloud-synced roots trigger idempotent alerts in GARDENER_CLOUD_ALERT_FILE without storing values)
- INV-RO-06: Read-Only External Observation (Foreign sources queried strictly read-only mode=ro)
- INV-TRAV-07: Path Traversal & Workspace Isolation (materialize() and absorb() sanitize target filenames, rejecting directory traversal attempts)
- INV-SUB-08: Unified Everything Substrate (Dual SQLite database substrate gardener.db / user.db unifying memory, tools, tasks, and documents in a single typed table)
- INV-DOCS-09: 1:1 Bilingual Parity & Machine-Readable Spec (Symmetrical 18-point documentation parity across English README.md and German README_de.md backed by llms.txt)
- INV-SLA-10: Open Source Governance & SLA (MIT License, public GitHub issues, and committed 48h initial response / 5d triage security SLA)
